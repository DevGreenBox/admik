## 🎯 РЕЖИМ ДЕМО «БОЕВОЙ СДЭК БЕЗ ОПЛАТЫ»

Для демонстрации клиенту нужен **боевой** СДЭК (реальные расчёты/ПВЗ/накладные в
кабинете СДЭК), но **без ожидания оплаты** (онлайн-кассы пока нет). Это включается
флагом `CDEK_CREATE_ON_ORDER=true` (Шаг 1). Тогда:
- при оформлении заказа на витрине отправление СДЭК регистрируется **сразу**, без оплаты;
- в карточке заказа админки кнопка **«Создать отправление»** доступна оператору и для
  **неоплаченного** заказа (ручной путь/повтор, если авто-создание не сработало).

⚠️ Чтобы создание отправления не падало, помимо ключей ОБЯЗАТЕЛЬНО задать:
- `CDEK_SHIPMENT_POINT` — код ПВЗ, откуда вы сдаёте посылки. Дефолтные тарифы **136/137
  идут «со склада»** → без этого кода СДЭК-заказ не создаётся (`cdek_shipment_point_required`).
- `CDEK_SENDER_NAME` (и желательно `CDEK_SENDER_PHONE`) — отправитель на накладной.

> Когда появится онлайн-касса — вернуть `CDEK_CREATE_ON_ORDER=false` (штатно накладная
> создаётся только после поступления оплаты).

## Шаг 1. Вписать боевые секреты в `/opt/admik/.env`
```
ssh -i ~/.ssh/admik_deploy root@admin.erfgq.website
nano /opt/admik/.env
```
Заполнить (сейчас пусты):
```dotenv
CDEK_ACCOUNT=<боевой client_id из ЛК СДЭК → раздел «Интеграция»>
CDEK_SECRET=<боевой client_secret оттуда же>
CDEK_CREATE_ON_ORDER=true                        # ДЕМО БЕЗ ОПЛАТЫ: накладная создаётся сразу при оформлении
CDEK_SHIPMENT_POINT=<код ПВЗ сдачи посылок>      # ОБЯЗАТЕЛЕН для тарифов «со склада» 136/137 (иначе создание падает)
CDEK_SENDER_NAME=<название/ФИО отправителя>      # нужно для создания накладной
CDEK_SENDER_PHONE=<телефон отправителя>          # желателен для накладной
CDEK_CRON_SECRET=<длинный случайный секрет>      # без него cron-роуты СДЭК отдают 503
CDEK_WEBHOOK_SECRET=<длинный случайный секрет>   # авторизация вебхука ?key=
# по необходимости: CDEK_SENDER_CONTACT_NAME=, CDEK_SENDER_EMAIL=, CDEK_SENDER_INN=
```
Случайный секрет удобно сгенерить: `openssl rand -hex 24`.
⚠️ Ключи живут ТОЛЬКО в `/opt/admik/.env` — в репозиторий не коммитятся.

## Шаг 2. Перезапустить app (подхватить .env)
```
cd /opt/admik && docker compose restart app
curl -s "https://admin.erfgq.website/api/health?deep=1"   # ждём "status":"ok"
```

## Шаг 3. Зарегистрировать подписку на вебхуки СДЭК
Админка → `https://admin.erfgq.website/admin/cdek` → карточка **«Подписка на вебхуки»** → кнопка **«Проверить подписку»**.
Она идемпотентно вызовет `POST /v2/webhooks` в кабинете СДЭК, чтобы СДЭК слал статусы на
`/api/cdek/webhook?key=<CDEK_WEBHOOK_SECRET>`. Отчёт покажет created/kept (секрет замаскирован).
_(В cron это НЕ подключено — регистрация через кнопку. Автоматизацию в cron-тик можно добавить отдельно.)_

## Шаг 4. Живая проверка на боевом контуре
1. Карточка заказа → блок «СДЭК» → **расчёт доставки** для реального города → реальная цена/срок (не mock).
2. **Список ПВЗ** для города → реальные пункты выдачи.
3. **Создать тестовое отправление** (маленькое) → в ЛК СДЭК появляется заказ, трек-номер в карточке.
4. Дождаться **вебхука статуса** (или ручной синк через cron-роут с `CDEK_CRON_SECRET`).
5. Проверить **печать накладной** (кнопка в карточке / роут `/admin/cdek/label`).

## Ограничения демо-режима и ops-безопасность (аудит 2026-07-09)

- **Вебхук-секрет в `?key=` попадает в access-логи.** СДЭК шлёт статусы на
  `…/api/cdek/webhook?key=<секрет>`; полная строка запроса пишется в логи Caddy/Next.
  Рекомендация для боя: как основной барьер использовать **IP-whitelist**
  (`CDEK_WEBHOOK_IPS` + `CDEK_WEBHOOK_TRUST_PROXY`), а логирование query для пути
  `/api/cdek/webhook` отключить/санитизировать. `?key=` оставить как резервную защиту
  (в кабинете СДЭК нельзя задать кастомный заголовок — секрет в URL это компромисс модели).
- **Режим «без оплаты» (`CDEK_CREATE_ON_ORDER=true`) синхронно регистрирует накладную
  внутри запроса оформления** (держит соединение БД во время POST в СДЭК до ~30с). Для
  **демо и низкого трафика — приемлемо**. Перед включением на РЕАЛЬНЫЙ поток заказов
  вынести регистрацию в фон/очередь (или полагаться на cron-подхват), иначе всплеск
  параллельных чекаутов при деградации СДЭК может исчерпать пул БД. Отдельная задача, не блокер демо.
